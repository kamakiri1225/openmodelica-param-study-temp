# eva4 実測との比較（温度管理モデル）

## どうモデル化したら温度データが合うようになったか

eva4 の実測は「同じ610W加熱でも 24.4℃ で保持」＝**温度管理（除熱）が入っている**。
モデルに **`TempControl`（目標温度へ除熱する冷却ループ）を追加**することで、
定常温度が eva5 の 37.7℃ から eva4 の **目標付近（≈24.5℃）に下がり、実測と一致**する。

- 温度管理**なし**（eva5_04）：Tss = 37.7℃（合わない）。
- 温度管理**あり**（eva4_01/02）：Tss ≈ Ttarget（≈24.5℃）に保持 → eva4 の 1次遅れ同定（Tss24.5, τ2.8h, RMSE0.03）に対応。

![温度管理の効果](img/eva4_control_effect.png)

**合わせこみノブ**：目標温度 `Ttarget`（= 保持温度）と `ctrl_k`（応答の速さ＝時定数）。
実測の保持温度 24.4℃・τ≈2.8h に合わせて `Ttarget`・`ctrl_k` を設定する。

## 各モデルと実測の比較（集中定数での応答）

![温度管理モデル(設定保持型 vs 冷却コイル型) と eva4 実測の比較](img/eva4_model_vs_exp.png)

| モデル | 立ち上がり | eva4適合 |
|---|---|---|
| PI設定保持型（`eva4_01_regLib` / `eva4_02_catalog`） | 速く平坦化 | RMSE **0.31℃** |
| **冷却コイル型（`eva4_03_coilCtrl`）** | **緩やかに平衡へ** | RMSE **0.11℃** |

- **保持温度はいずれも ≈24.5℃**で、eva4 のプラトー（24.4℃）と一致。
- **PI設定保持型（A/B）**：目標温度へ“きつく”保持するため速く平坦化 → 実測の緩やかな立ち上がりと合わない。
  なお A（能力上限なし）と B（3.5kW上限）は入熱610W ≪ 3.5kW でほぼ同一。
- **冷却コイル型（C）★**：除熱=`UA_cool×(水温−Tcool)`（UA_cool=57 W/K, Tcool=14℃）で**水温依存**のため、
  平衡へ **τ≈2.8h でゆっくり接近** → **立ち上がりまで実測に一致（RMSE 0.11℃）**。
  実機オイルコンの「能力が液温で変わる」特性（`002_...` の能力特性図）とも物理的に整合。**推奨モデル**。
- さらに詰めるなら：外気を測定値（eva5 の 4-9 のような日中上昇）で時間変化させる、`Tcool`/`UA_cool` を微調整。

## 2モデルの比較（A: regulator / B: カタログ）
本ケースは入熱610W ≪ 冷却能力3.5kW のため、A（上限なし）と B（3.5kW上限）は**ほぼ同一の保持挙動**。
→ eva4 の再現性は両者同等。**冷却能力の違いが効くのは、入熱が能力に近い/超える高負荷時**（B は頭打ちで温度上昇）。

## 実行手順（Windows OpenModelica）
```bat
cd eva4
:: A(regulatorライブラリ版)
"C:\Program Files\OpenModelica1.26.3-64bit\bin\omc.exe" run_sim_01_regLib.mos
:: B(カタログ準拠 3.5kW)
"...omc.exe" run_sim_02_catalog.mos
:: ユーザ作モデル
"...omc.exe" run_sim.mos          :: ana001_Tank_004
python compare.py                  :: 実測と重ねて比較図
```
- `TempControl` の `Ttarget`（既定=外気24.5℃相当）と `ctrl_k` を、実測の保持温度・立ち上がりに合わせて調整。
- 5.0kW 版にするには `cooling_capacity = 5000` に変更（B）。

## 注記
- こちらに omc が無く**コンパイル確認は未実施**。OMEdit で `model/eva4_02_catalog.mo` を開いて実行し、
  エラーが出たら内容（特に `LimPID` の初期化・`tempControl` 接続）を共有ください。
- `TempControl` は冷却のみ（`yMax=0`）。実機オイルコンも通常は冷却。初期が目標より低い場合は加熱源（サイクロン）で昇温してから保持に入る。
